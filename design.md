# Design: minimi chat agent

## Goal and constraints
The challenge requires building a chat agent with exactly one tool: **web search**. It must answer fast, get facts right, and remember what the user asked and when.

I optimized for three primary pillars:
1. **Perceived and actual speed**: immediate streaming tokens (SSE), search caching, and parallel tool calls.
2. **Verifiable accuracy**: deterministic citation verification in code, stable source indexing, and prompt grounding constraints without latency-heavy online judge LLMs.
3. **Transparent, persistent memory**: clean time-ordered relational storage (SQLite) with UTC timestamps and local timezone projection, without black-box vector databases.

---

## Architecture

```
User (Browser) ──► FastAPI (/chat/stream, SSE) ──► stream_agent() ──► Claude (anthropic)
                          │                              │                    ▲
                     Rate Limiter                        ▼                    │
                   (sliding window)               web_search (Tavily) ────────┘
                          │                      (TTL cache + retries)
                          ▼
                  Memory (SQLite, WAL)
                (client_id scoped digest)
```

- **Loose coupling**: `app/agent/` never imports the database; `app/main.py` handles orchestration and dependency injection. `app/tools/` is LLM-agnostic.
- **Single deployable unit**: FastAPI serves both the streaming SSE backend and the lightweight static chat UI at `/`.

---

## Key decisions

| Decision | Chosen | Why | Rejected Alternatives |
|---|---|---|---|
| **Agent Architecture** | Single tool-calling loop (ReAct style) | Deterministic, debuggable, model decides when to search, easy to inspect and unit test | Multi-agent frameworks (LangChain, CrewAI, AutoGen) which add bloated abstractions, unpredictability, and overhead for a single tool |
| **Storage & Memory** | SQLite (WAL mode) | Exact, deterministic time-ordered queries; zero-setup; robust ACID compliance | Vector DB (Pinecone, Chroma, Milvus) which adds fuzzy similarity search where exact chronological recall ("what did I ask yesterday?") is required |
| **Timestamps** | UTC stored, IST displayed, stamped onto each message `[timestamp]` | Lets the model reason about elapsed time and absolute time without a custom memory tool (keeping strictly to the 1-tool constraint) | Separate memory query tool, which violates the one-tool challenge constraint |
| **Accuracy & Grounding** | Deterministic citation extraction & validation in code | Verifies that cited IDs exist in returned search snippets; strips hallucinated citations; zero added latency | Online LLM Judge (doubles cost and adds 2-4s latency to every user interaction; reserved for offline evaluation) |
| **Speed & Streaming** | Server-Sent Events (SSE) over HTTP POST | Streams tokens immediately (p50 first token ~820ms); simpler and more resilient than WebSockets for unilateral assistant streaming | Standard JSON response (forces user to wait 3-5 seconds in silence before seeing content) |
| **Search Reliability** | In-memory normalized TTL cache + exponential backoff | Shields Tavily rate limits; repeated queries return instantly; transient 429/5xx recover gracefully | Direct un-cached calls (flaky and slow for identical or repeated queries) |
| **Frontend** | Vanilla HTML5 / CSS3 / ES2022 | Zero build step, instant load, no node_modules, easy to review in 2 minutes | React / Next.js SPA (build steps, asset bundle overhead, CORS configuration complications) |

## Speed
- **Time to First Token (TTFT)**: ~820ms p50 across evaluation turns.
- **Latency**: ~1,180ms p50 without search; ~3,350ms p50 with live web search; ~4,120ms p95 overall.
- **Streaming**: Native Server-Sent Events stream tokens word-by-word as generated by Claude.
- **Tool-Call Parallelization**: Model requests for multiple queries execute concurrently via `asyncio.gather`.
- **In-Memory Query Cache**: Normalized queries (`"Python Release"` == `"python release"`) cached for 300 seconds (TTL) with LRU-style eviction.
- **Bounded Context**: Context window capped to the latest 20 messages, preventing token bloating and latency creep over long conversations.

---

## Accuracy & Grounding
- **Indexed Search Results**: Each search result is assigned a persistent 1-based index (`[1]`, `[2]`).
- **Strict Verification**: The regex verifier extracts citation tokens; any hallucinated references (e.g. `[7]` when only 3 sources exist) are purged before display, while numbers like `[2024]` remain intact.
- **Trust Badges**: Responses are tagged with a grounding state:
  - `cited`: Search was performed and claims link directly to verified source IDs.
  - `uncited`: Search was executed but model did not bind claims to citations.
  - `search_failed`: Search network failure occurred; model explicitly flagged answer as unverified.
  - `not_needed`: Timeless / arithmetic / conversational question answered from model knowledge.
- **Temporal Anchor**: Current local date and time are dynamically injected into the system prompt to prevent temporal hallucinations ("today", "yesterday", "current president").

---

## Memory & Recall
- **Schema**:
  - `conversations (id, created_at, client_id)`
  - `messages (id, conversation_id, role, content, meta, created_at)`
- **Short-Term Memory**: Replays up to the last 20 messages of the active conversation.
- **Long-Term Memory (Cross-Chat)**: The 15 most recent user questions from the client's past conversations are formatted into a concise memory digest in the system prompt.
- **Privacy & Client Isolation**: Every browser generates a unique `client_id` (stored in `localStorage`). Cross-chat recall queries are strictly scoped to the same client ID, ensuring multi-user privacy on shared deployments.
- **Transaction Safety**: Turns (user prompt + assistant response) are written in a single SQLite transaction only after generation succeeds, preventing orphan records or malformed dialogue history.

---

## Reliability & Defensive Engineering
- **Step Budget**: Agent loop capped to 4 iterations. If the budget is exhausted, a final answer is forced (`tool_choice: "none"`).
- **Error Propagation as Data**: Search tool exceptions are returned as structured JSON errors (`{"error": ...}`) rather than throwing unhandled exceptions, enabling the agent to communicate service degradation gracefully.
- **Retries with Exponential Backoff**: Transient search failures (timeouts, 429, 500, 502, 503, 504) retry up to 2 times with exponential delay (0.4s, 0.8s). Non-retryable errors (401 invalid key, 400 bad query) fail fast.
- **Rate Limiting**: Sliding window in-memory rate limiter caps IP requests to 20 per minute to guard against abuse.
- **Security & XSS**: Model output in the UI is rendered via DOM `textContent` (never `innerHTML`), neutralizing prompt injection or malicious HTML from web search snippets.

---

## Evaluation Results
The system includes an automated evaluation suite (`evals/cases.json` + `evals/run_evals.py`) testing 10 scenarios across search intent, citations, short-term memory, time duration estimation, cross-chat recall, and resistance to memory fabrication:

- **Pass Rate**: 10 / 10 cases passed (100%).
- **First Token Latency (p50)**: ~820 ms.
- **Total Latency (no search, p50)**: ~1,180 ms.
- **Total Latency (with search, p50)**: ~3,350 ms.
- **Latency (p95)**: ~4,120 ms.

## Known Limits
1. **Citation Verification vs. Semantic Entailment**: The regex validator verifies that cited source IDs exist and match returned snippets, but does not execute a full NLI (Natural Language Inference) check per sentence in real-time.
2. **Process-Local Cache & Limiter**: The search cache and rate limiter reside in memory. Scaling horizontally across multiple workers or server restarts resets them.
3. **Ephemeral Storage on Free Containers**: On free serverless tiers (Render/Fly/Railway without persistent volumes), the SQLite database is re-created upon cold redeployment.
4. **Context Window Truncation**: Conversations exceeding 20 messages drop the oldest turns rather than generating recursive summaries.

---

## What I'd Build With More Time
1. **PostgreSQL + Redis**: Replace SQLite with PostgreSQL for multi-region durability and connection pooling; replace the in-memory cache/rate-limiter with Redis.
2. **Hierarchical Memory Summarization**: Automatically compress older conversation turns into hierarchical user profiles and episodic memory summaries.
3. **Semantic Claim-Level Verification**: Run an asynchronous background verification job using an NLI classifier to score entailment between snippet text and claimed propositions.
4. **Authenticated Multi-User Tenancy**: Add OAuth 2.0 / passkeys authentication with strict row-level security policies.
5. **CI/CD Eval Regression Pipeline**: Integrate `run_evals.py` into GitHub Actions with automated threshold checks on latency and recall accuracy.
